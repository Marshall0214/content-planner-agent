# 需求与成功条件

目标用户为内容运营。输入主题、整数模拟预算、带时区截止时间、合成素材/费表目录、明确硬需求和软偏好，输出可审阅活动方案、脚本正文、引用、本次准备步骤与依赖、实际尝试、工具结果、费用和保存事实。

四工具为search_materials、generate_script、estimate_plan、save_plan。模型负责查询、候选、替代、重试和有依据停止；程序负责参数、预算、时间、依赖、状态、幂等和正常保存确认。离线脚本只证明流程；真实模型需观察工具反馈后再自主选择。

方案最小字段：目标、受众、核心信息、渠道、脚本正文、合成来源、建议运营任务及依赖、风险假设。营销任务全部NOT_STARTED。成功还需正文与引用有效、受支持硬需求满足、费用不超预算、有效时钟满足准备截止、保存回执确认。30秒/竖屏/分镜不作通用门槛；用户明确硬需求不能删，超出本地有限核验能力就说明不支持并请求澄清。

正常、缺预算、缺期限、工具失败、超预算、重复均需覆盖。保留成功产物；明确失败不能记成功；UNKNOWN不能假定免费/失败/未提交。最后合法调用确认保存可以完成；未完成且额度耗尽直接停止。程序不越过上限补模型或工具调用。

预算只覆盖准备工具，不包含API账单、真实制作、版权采购和投放。截止约束准备并保存完成，不是活动执行结束。基础/高级两模式提供同样核心产物。费表和素材请求内冻结，估价每次读新账本和时钟。

整体验收还需两类合格真实路径：①超预算反馈后的替代/调整/有依据停止；②工具失败或部分成功后的改查询/复用重试/调整/有依据停止。至少三组实际输入/输出/记录覆盖专项点。12→8不是唯一轨迹；离线Mock不能补真实证据。

最终按原题最低要求复核：现有场景、两条真实反馈调整记录及至少三组材料具备，建议带限制说明提交，见[最终交付](07-final-delivery.md)。用户已接受C1–C4，见[确认记录](06-content-review.md)；编辑附录与原始模型方案分开。工时和固定分钟数不是通过门槛，用户确认实际用时不到6小时（无精确分钟/分项计时）；P1不纳入最低要求。

## 题面与附加评测的边界（2026-11-11）

故障盲测隔离是项目后来增加的实验条件，原题未明确要求；历史盲测不合格保留。已有生成失败记录有实际错误、回传及模型重试，可带请求键提示的局限用于原题工具失败与第二类动态路径证据，不能据此宣称无预提示恢复能力。SAVE_TEMPORARY保存恢复是选定的具体场景，未触发仍未通过，但不使已观察到的其他工具恢复失效。最低要求满足的技术判断不等于全部项目实验、产品质量或生产能力通过。
